# WBS Google Calendar 삭제 동기화 트러블슈팅 2026-07-03

## 증상

- WBS 간트에서 줄을 삭제했는데 Google Calendar 쪽 일정이 바로 사라지지 않거나, 반대로 Google Calendar에는 이미 없는데 Bubli 화면에는 WBS 줄이 남아 보일 수 있다.
- 사용자는 WBS 줄을 삭제했다고 인식했는데 외부 캘린더 반영이 늦으면 같은 줄을 다시 삭제해야 하는 것처럼 느껴진다.

## 현재 기준

- WBS 줄 자체의 원본은 Bubli DB의 WBS 항목이다.
- WBS 기간 표시는 `schedules.wbsItemId`로 연결된 일정으로 저장한다.
- 현재 백엔드는 프로젝트룸 전용 보조 캘린더가 아니라 개인 Google 기본 캘린더 이벤트를 생성·수정·삭제한다.
- Google Calendar 삭제가 실패해도 Bubli WBS 삭제를 막지 않는다. Bubli DB 삭제가 성공하면 화면에서는 삭제 확정으로 처리하고, Google 삭제 실패분은 재동기화 또는 재시도 대상으로 본다.

## 삭제 흐름

1. 프론트가 연결된 일정이 있으면 `DELETE /api/schedules/{scheduleId}`를 먼저 요청한다.
2. 일정 삭제 요청이 실패하거나 Google 쪽 이벤트가 이미 없어도 프론트는 화면 일정 캐시에서 해당 일정을 제거한다.
3. 프론트가 `DELETE /api/wbs-items/{id}`를 요청한다.
4. WBS 삭제가 성공하면 Bubli 화면에서는 해당 WBS 줄을 제거한다.
5. WBS 삭제가 실패하면 WBS가 원본이므로 화면에 남겨두고 다시 삭제할 수 있게 한다.

## 고쳐야 할 점

- 백엔드는 Google 이벤트가 이미 없다는 응답을 삭제 성공으로 간주해야 한다.
- 백엔드는 WBS 삭제 성공 뒤 Google 삭제 실패분을 별도 재시도 대상으로 남겨야 한다.
- 동기화가 다시 들어올 때 `googleEventId`가 더 이상 Google Calendar에 없으면 연결된 로컬 schedule을 삭제된 외부 일정으로 정리해야 한다.
- 프로젝트룸별 Google `다른 캘린더` 분리는 가능하지만, 별도 OAuth scope와 프로젝트룸별 `calendarId` 저장이 필요하므로 달력 담당 작업으로 분리한다.

## 프론트 보정

- WBS 삭제 성공 시 화면은 즉시 제거한다.
- 일정 삭제 실패 시 안내는 `삭제됨 — 캘린더 동기화 대기`로 표시한다.
- WBS 삭제 실패 시에는 `삭제 실패 — WBS가 서버에 남아 있습니다`로 표시한다.
- 간트 스크롤은 드래그/삭제 직후 자동 보정으로 튀지 않게 고정한다.
